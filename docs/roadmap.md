# Roadmap

The milestones in build order, and the check that says each one is done.

## Goal

Private groups first. The milestones after M13 build toward one test: a small group of friends (5 to 12) has its own place on Pigeon, and it works even when they're never online at the same time. The Lighthouse comes first because invites, letters, device sync, groups and push all need the same thing from it: somewhere that holds sealed mail while people are away. Public places wait until their moderation is designed.

## Decisions before code

- M15 follows [0026](decisions/0026-pair-rooms-from-a-shared-secret.md), now accepted. It comes first because the leak it closes is live today, and every friendship made before it has to move.
- M13 follows [0024](decisions/0024-a-signed-list-of-devices.md), now accepted, with only the first device managing the list, and its recovery key follows [0027](decisions/0027-a-recovery-key-that-outranks-devices.md), now accepted: it outranks every device, makes whichever device it's used on the writer, and only it can replace itself. It comes before M7 so invites and letters are sealed to every device from the start; M8 adds the self space that syncs your own data between devices.
- M16 needs a decision: the Lighthouse's mailbox replaces the Worker route M7 used to plan, so the brief's rule on servers stands as it is. It covers addressing by rotating tags, what the Lighthouse sees, which Lighthouse an invite names, who runs the official one, and a WebRTC library for Node (a dependency, asked first). The mailbox [0024](decisions/0024-a-signed-list-of-devices.md) and [0026](decisions/0026-pair-rooms-from-a-shared-secret.md) call M7's is this one.
- M14 needs a decision on push subscriptions, since the Lighthouse would hold them.
- M4's decision covers forward secrecy and rotating tags.
- M8's shared spaces get a decision, written with MLS in mind.
- M6 needs a decision on Lighthouses run by others: trust defaults, what an operator sees, and signed release builds for a Lighthouse that serves Pigeon.
- M12's release notes are [0025](decisions/0025-release-notes-for-people.md), which supersedes the "no changelog file" part of [0021](decisions/0021-releases-with-release-please.md).
- M10's birds, M11's cursors and Coo are drawn for Pigeon, never copied ([0007](decisions/0007-original-and-openly-licensed-assets-only.md)).

## Later, not yet scheduled

- Public places, after M6: a lobby, public groups, starter pages and Coo as a bot (M11 gives him his body), with moderation designed first. Moderation stacks: Lighthouses and friends publish signed labels and block lists, and you choose whose to follow; a report button and a written policy come before any public feature, and a decision on how labels stack before any code.
- Message boards on the peer net, after M5 and public places: public spaces with threads ordered by bump, an owner's moderation log and proof-of-work per post; pseudonymous, never anonymous, and text only, with no image uploads.
- "Pocket keeps watch": a native Android mode that turns a spare phone left on power and Wi-Fi into a small Lighthouse for you and your friends, like Briar Mailbox.
- Letting more than one device manage the list. It needs its own decision: [0024](decisions/0024-a-signed-list-of-devices.md) keeps the list to one writer because three reviews broke every way of letting several devices change it at once. Handing the writer's role to another device is done with the recovery key ([0027](decisions/0027-a-recovery-key-that-outranks-devices.md)).
- A transparency log of device lists, kept and cross-checked by Lighthouses, so a fake device slipped into someone's list gets noticed.
- Handles verified by a domain (`toms.dev` publishing `pigeon=<PeerId>`), optional and beside petnames.
- Real-time games, games made by other people (sandboxed, ask first), and hidden-hand card games.

Not planned: a blockchain. Nothing in Pigeon needs strangers to agree on one global order; signatures, petnames and the transparency log cover what it would.

## Current state

M1 is built. The desktop boots offline with Read Me open; the Messenger shows the real, empty state, and `?demo` (or "See a sample conversation") plays the Desktop board's sample, labelled as such. Letters, Shared Files and Pigeon Explorer open an in-world "still being built" message. Window positions and settings live in memory only until M2 adds storage.

M2 is built, pending its done check across two real networks. Each visitor gets a WebCrypto identity kept in IndexedDB; Add a Friend shares a one-use invite as a code to type, a short link and a QR code, and adds a friend only after showing who answered and their fingerprint; the Messenger lists real friends with presence, and conversations carry messages, buzzes and "is writing" (shown as the transcript's last line) over Trystero, note when the friend comes online or goes offline, and keep chats and catch them up between visits. The sample is still there, labelled as such. `mise run e2e` pairs and chats two isolated browsers over the public relays. Shell settings and window positions still live in memory only. On phones Pigeon runs on the Kestrel Pocket ([0019](decisions/0019-the-kestrel-pocket-phone-layout.md)).

M12 is built, pending its done check on the next release. Changelog.txt sits on the desktop with notes for 0.2.0 to 0.4.0, and the release-please workflow drafts each new release's section on the release PR for the author to rewrite ([0025](decisions/0025-release-notes-for-people.md)). A returning visitor on a newer version gets a balloon, "Pigeon was updated to 0.5.0. See what's new?", once; a first visit gets none.

M15 is built, pending a release and its done check on the live relays. Pairing sends a pair secret in `pair-accept`, and friends meet in a room named from it and the UTC date, locked with a password derived from it, with both days' rooms joined around midnight ([0026](decisions/0026-pair-rooms-from-a-shared-secret.md)). Friends from before it move the next time they meet in the old room, and then stop joining it. The browser is asked once to keep Pigeon's storage. On an iPhone or iPad in a Safari tab, a balloon (once) and Add to Home Screen.txt on the desktop say how to keep Pigeon, and a web app manifest makes the Home Screen icon open Pigeon as its own app, on iPhone and Android alike; Web Push and the rest of installing (an install prompt, offline start) stay with M14. Always Go Through the Relay is in the Messenger's File menu and in Settings, under Connection.

M10 is under way. Everyone has a pixel pigeon drawn from their id, frozen per version with the version said in `hello` ([design.md](design.md#avatars)), shown in the buddy list, conversations, profiles, Blocked People, the Pigeon menu, Add a Friend, Today on the Pocket and balloons, pending its done check.

M13 is partly built: linking, one friend across devices, removing, device fingerprints in the list, noticing a copied browser profile (with Pigeon kept to one tab, [0028](decisions/0028-one-tab-and-copied-profiles.md)) and export and import ([0029](decisions/0029-your-data-in-a-file-for-your-own-devices.md)) are done, pending a release and the first half of its done check on two real devices; Save conversation as, and the recovery key are still to come. Each device keeps its own key, tied to one identity by a signed device log ([0024](decisions/0024-a-signed-list-of-devices.md)). File, Link a Device shows a code and QR code; the new device opens the link or types the code in Link to My Other Device, both show the same 6-digit check, and confirming on the old device hands over the name, friends (with their pair secrets), blocks and settings. Only the first device links and removes devices; My Devices lists them, each with its own fingerprint, with Remove there. A stolen second device can't touch the list. Friends see one friend with several devices, and messages from either device reach the other, through the friend or straight between your devices in the pair room. Your devices also meet in a self room, so removals reach them with no friend online. Friends on a Pigeon from before device logs hear only your first device until they update. Profiles are copied when linking, not kept in step; M8's self space does that.
